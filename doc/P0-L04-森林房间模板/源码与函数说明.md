## 2. `src/entity/level.cpp`

### `void Level::apply_room_camera_limits()`

**调用时机**：`Level::_ready()` 末尾，玩家实例化并 `spawn_player_at_marker()` 之后。

**逻辑**：

1. 若 `m_player == nullptr` 则返回
2. `m_player->find_child(name::level::player_camera, true, false)` 取 `Camera2D`
3. 通过 `camera->set("limit_*", ...)` 设置边界（godot-cpp 未绑定 typed setter）
4. `limit_smoothed = true`

**边界值**：

| 属性 | 值 |
|------|-----|
| `limit_left` | `-1000` |
| `limit_right` | `1000` |
| `limit_top` | `-750` |
| `limit_bottom` | `750` |

## 3. `src/main.cpp`

### `Main::Main()` 构造

**变更**：`m_active_level` 加入 `MainSubViewport`，而非 `MainCanvasLayer`。

```cpp
godot::SubViewport* game_viewport = gdcast<godot::SubViewport>(
    m_main_dialog->find_child(name::dialog::game_sub_viewport, true, false));
game_viewport->add_child(m_active_level);
```

**原因**：`main_dialog.tscn` 中游戏画面与 `HudCanvasLayer`（血条）同在 SubViewport 内分层；Level 作为世界根节点不应挂在 HUD 的 CanvasLayer 下。

## 4. `src/entity/character/character.cpp`

### `void Character::_ready()`

**变更**：取消注释 `m_camera->make_current()`。

**原因**：SubViewport 内须显式激活跟随相机，否则锁边 limit 不生效或取景异常。
